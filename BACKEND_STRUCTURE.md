# Структура backend

Актуальная серверная часть объединена в main вместе с frontend. Общий запуск,
окружение и семь тестовых аккаунтов описаны в [README](README.md).

## Модули

| Путь | Ответственность |
|---|---|
| app/main.py | FastAPI, маршруты, общие ошибки, healthcheck |
| app/api/routes | Вход/профиль, клиентские заявки и документы, очередь и действия сотрудника |
| app/api/dependencies.py | JWT, пользователь БД, проверка роли |
| app/api/versioning.py | Строгая версия из JSON; совместимость с legacy query |
| app/schemas | Pydantic DTO, строки рублей, валидация полей |
| app/core | Настройки, безопасность, ошибки и политика продукта |
| app/services/auth_service.py | Проверка пароля, выпуск JWT, связанный профиль |
| app/services/application_service.py | Черновики, отправка, дозаполнение, повторы, согласие, ручное решение и файлы |
| app/services/source_data.py | Проверка и нормализация входных данных источников |
| app/services/credit_evaluation.py | Итоговое решение, стоп-факторы и полнота сведений |
| app/services/credit_math.py | Чистый расчёт факторов, PD, ставки, аннуитета, безопасной суммы |
| app/integrations | Локальные синтетические моки ФНС/БКИ |
| app/repositories | SQLAlchemy-запросы и загрузка связей |
| app/models | Семь таблиц, связи и версия заявки |
| app/db | База моделей, движок и сессия |
| app/seed_test_users.py | Идемпотентное создание пяти клиентов и двух сотрудников |
| migrations | Четыре миграции Alembic до текущей схемы |
| tests | API/расчёт на SQLite, отдельные миграции и конкуренция на PostgreSQL |

Поток запроса: маршрут → сервис → репозиторий/модель → БД. Расчётный модуль
не зависит от HTTP, интеграций и БД. Публичной регистрации нет; учётные записи
заводятся доверенным процессом. Профиль клиента определяется по JWT/БД,
клиентский client_id не является основанием доступа.

## Процесс и хранение

Создание черновика, PATCH, submit, fill, sign и действия сотрудника реализованы.
ФНС/БКИ вызываются синхронно; проверки, исходные данные, решение и история
фиксируются одной транзакцией. При конфликте версии операция откатывается,
возвращается 409. CHECKING сохраняется в истории, ответ содержит итоговый статус.

Скоринг нормирует пять факторов, демонстрационная PD определяет ставку,
аннуитет и DSCR ограничивают безопасную сумму. Уменьшенная сумма возвращается
как counter-offer. Ручное одобрение использует сохранённые проверки и ту же
политику; SIGN проверяет целостность уже сохранённого предложения.

Метаданные документов находятся в БД, байты — в постоянном UPLOAD_DIR.
Скачивание требует JWT владельца или сотрудника. Подписание и выдача
смоделированы; реальных переводов, ЭП и внешних запросов ФНС/БКИ нет.

Compose запускает PostgreSQL 16, API и frontend/Nginx. API применяет миграции
и выполняет seed при включённом SEED_TEST_USERS. Повторный seed не меняет
пароли существующих аккаунтов. БД и файлы сохраняются в двух именованных томах.
