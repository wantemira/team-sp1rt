# Версии и обновление зависимостей

Проверяемая среда backend — Python 3.12.15 в Linux-контейнере. Версия также
указана в `.python-version`. `requirements.txt` — полный перечень точных
версий рабочих библиотек, включая транзитивные зависимости, снятый с
проверенной сборки 26.10.2026. `requirements-dev.txt` подключает тот же файл
и добавляет точные версии pytest/httpx и их зависимостей. В рабочий образ
тестовые библиотеки не устанавливаются.

Образы Python, Node.js 20, Nginx и PostgreSQL 16 закреплены digest в Dockerfile
и Compose. Это индексы образов с несколькими архитектурами; проверка выполнена
на Linux arm64. Обновление тега в registry не меняет выбранный digest.
Frontend использует `package-lock.json` и `npm ci`; `npm install` для обычного
запуска не требуется.

## Установка

```bash
python -m pip install -r requirements.txt
# Для разработки и API-тестов:
python -m pip install -r requirements-dev.txt
python -m pip check
```

Для полностью одинаковой среды используйте Docker. Локальная установка на
других ОС не проверена тем же набором тестов: uvloop включён только вне Windows
и PyPy, colorama закреплена для Windows. Файлы фиксируют версии, но не хеши
архивов Python-пакетов и не подменяют проверку их происхождения.

## Контролируемое обновление

1. Создать чистую среду на выбранной версии Python. Обновлять только нужные
   библиотеки; сохранить рабочие версии остальных. `pip check` должен пройти.
2. Сверить зависимости через `python -m pip inspect` и `python -m pip freeze`.
   Обновить точные версии и транзитивные зависимости в requirements.txt;
   тестовые библиотеки держать в requirements-dev.txt. Не включать глобальные
   инструменты разработчика или URL локальных путей из произвольного freeze.
3. Установить оба файла с нуля, повторить `pip check`, API-тесты и общий запуск.
   Проверить основные браузерные сценарии, если затронуты API или веб-среда.
4. При обновлении образов выбрать новый digest из registry, сохранить основной
   номер PostgreSQL или отдельно подготовить миграцию данных между версиями.
5. Зафиксировать файлы и результаты проверки одним отдельным коммитом.

Проверка API с тестовыми инструментами в отдельном временном контейнере:

```bash
docker compose run --rm --no-deps api sh -c "pip install -r requirements-dev.txt && pip check && python -m pytest"
```

Эта команда проверяет SQLite-сценарии, не меняет рабочий образ и пропускает два
PostgreSQL-теста без CREDIT_TEST_POSTGRES_URL. Для них нужна отдельная тестовая
БД/схема по инструкции в README; не запускайте тесты на ценных данных.
