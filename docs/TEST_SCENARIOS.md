# Проверка прототипа

## Подготовка

Запустите общий Docker-стенд по [README](../README.md), дождитесь готовности
трёх сервисов. Вход через http://localhost:8080. Все описанные операции создают
синтетические заявки; используйте отдельный тестовый стенд. Пароль семи seed-
аккаунтов задаёт TEST_USERS_PASSWORD. Если аккаунты уже существуют, seed не
меняет их пароли — используйте пароль, с которым они были созданы.

## Коллекция Postman / Newman

Импортируйте [credit-demo.postman_collection.json](credit-demo.postman_collection.json)
в Postman. Задайте переменную окружения `demo_password`, равную паролю стенда,
и при необходимости `base_url` (по умолчанию http://localhost:8080/api/v1).
Запустите коллекцию целиком сверху вниз. JWT, ID и числовые версии берутся
из ответов автоматически; вручную копировать их не нужно. Для отдельной папки
с повтором ФНС сначала выполните вход сотрудника из папки 2.

В CLI с Node.js 20.20+ можно использовать Newman 6.2.1. Предварительно задайте
TEST_USERS_PASSWORD в окружении терминала:

```bash
npx --yes newman@6.2.1 run docs/credit-demo.postman_collection.json \
  --env-var "demo_password=$TEST_USERS_PASSWORD" --bail
```

Для другого адреса добавьте `--env-var base_url=http://127.0.0.1:18080/api/v1`.
Пароли и JWT не сохранены в коллекции. Не коммитьте экспорт окружения с ними.

Проверенный результат: 27 запросов и 57 утверждений, без ошибок, через
production Nginx → API → PostgreSQL 16. Коллекция создаёт новые заявки при
каждом запуске и не удаляет результаты. Это проверка HTTP-процесса; браузерный
интерфейс отдельно покрывается Playwright.

## Основной показ: ИП и counter-offer

1. Войти как demo.ip@example.com, выбрать оборотный кредит.
2. Создать черновик на 1 000 000 ₽, 24 месяца. ИНН берётся из профиля клиента.
3. Сохранить, перечитать черновик: сумма и срок сохранены на сервере.
4. Отправить на рассмотрение. ФНС/БКИ — локальные синтетические интеграции.
5. Получить APPROVED с `offer.kind=COUNTER_OFFER`, около 609 641 ₽. Проверить
   объяснение, ставку, месячный платёж и DSCR ≥ 1,35. Сумма рассчитана, а не
   зашита в интерфейс. CHECKING виден в истории одной синхронной операции.
6. Нажать «Согласен с предложением», проверить условия и подтвердить.
7. Получить ISSUED, перезагрузить страницу: предложение и даты сохранены.
8. Повторное согласие через API даёт 409; клиентский токен не открывает очередь
   сотрудника (403). Оба случая включены в коллекцию.

## Ручное рассмотрение

1. demo.review@example.com: отправить 1 млн ₽ / 24 месяца → MANUAL_REVIEW.
2. test.employee1@example.com: открыть очередь и карточку. Проверить выручку
   2,4 млн ₽/год, расходы 1,2 млн ₽/год, поток 100 тыс. ₽/мес, текущие платежи
   0 ₽, 6 задержанных платежей из 24, отсутствие текущей просрочки.
3. Запросить годовую выручку с причиной и комментарием → NEEDS_INFO.
4. Клиент передаёт 2400000.00 → повтор расчёта → MANUAL_REVIEW.
5. Сотрудник одобряет 1000000.00 с комментарием. Сервер рассчитывает ставку,
   проверяет DSCR и сохраняет автора плюс исходное автоматическое заключение.
6. Клиент подтверждает условия → ISSUED. Всё включено в папку 2 коллекции.

## Недоступность источника и дозаполнение

test.client3@example.com: создать новую заявку 1 млн ₽ / 24 месяца. Первый
вызов ФНС по этой заявке даёт TIMEOUT, результат MANUAL_REVIEW; сотруднику
доступен только RETRY_CHECKS. После повтора — NEEDS_INFO. Клиент передаёт
выручку 6000000.00, расчёт завершается APPROVED. Папка 3 коллекции проверяет
этот путь без подмены HTTP-ответов.

Запуск pytest/PostgreSQL и Playwright описан в [README](../README.md) и
[frontend/README](../frontend/README.md). В части браузерных тестов редкие
конфликты и недоступность источников воспроизводятся подменой ответов — это

Для проверки хранения: сохранить черновик, согласовать вторую заявку,
загрузить документ; выполнить `docker compose down`, затем `up -d --wait`
с тем же .env и томами. Проверить статусы, условия, историю и байты файла.
`down -v` для такого сценария не подходит: он удаляет тома.

## OpenAPI

Точная схема доступна в http://localhost:8000/openapi.json, Swagger — `/docs`.
Корневой [api.yaml](../api.yaml) — снимок этой схемы OpenAPI 3.1.0, а не отдельно
поддерживаемый вручную контракт. После изменения маршрутов/DTO обновить его
на запущенном сервере (PyYAML уже входит в requirements.txt):

```bash
python - <<'PY'
import json
from pathlib import Path
from urllib.request import urlopen
import yaml

with urlopen('http://localhost:8000/openapi.json') as response:
    schema = json.load(response)
Path('api.yaml').write_text(
    '# Снимок FastAPI /openapi.json; обновление: docs/TEST_SCENARIOS.md\n'
    + yaml.safe_dump(schema, allow_unicode=True, sort_keys=False), encoding='utf-8'
)
PY
```

После обновления сверить схему с сервером и повторить затронутые сценарии.
Описание семантики прав, состояний и JSON-версии находится в [Api.md](../Api.md).
