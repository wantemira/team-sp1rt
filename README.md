# Кредитный кабинет — team-sp1rt

### От заявки на оборотный кредит до понятного решения — в одном сервисе

**Умный кредитный кабинет** — веб-прототип оборотного кредитования для бизнеса. Он объединяет кабинет клиента, рабочее место сотрудника банка и механизм расчёта кредитных условий.

Цель решения — показать полный путь заявки: от потребности бизнеса в финансировании до оценки, предложения условий, согласия клиента и моделирования выдачи. На каждом этапе участники видят актуальный статус и следующий доступный шаг.

> Клиент понимает, какие условия ему предлагают и что делать дальше. Сотрудник видит контекст заявки, результаты проверок и историю принятого решения.

## Какую задачу решаем

Бизнесу нужны средства на закупку товара, оплату поставщикам и покрытие кассовых разрывов. При обращении за кредитом клиенту важно понимать, какую сумму он может получить, по какой ставке и на каком этапе находится заявка.

Сотруднику банка нужна единая картина: сведения о компании, результаты проверок, расчёт условий и предыдущие действия по заявке.

Наше решение объединяет эти задачи в одном интерфейсе и делает процесс рассмотрения последовательным и прозрачным.

## Два кабинета — один процесс

| Кабинет клиента | Кабинет сотрудника |
| --- | --- |
| Создание заявки на оборотный кредит | Просмотр очереди и карточек заявок |
| Указание суммы, срока и финансовых данных бизнеса | Изучение данных компании и результатов проверок |
| Отслеживание статуса рассмотрения | Просмотр расчёта ставки и доступной суммы |
| Предоставление запрошенных уточнений | Запрос дополнительной информации |
| Просмотр исходного или встречного предложения | Принятие решения и формирование предложения |
| Согласие с предложенными условиями | Фиксация основания решения и комментария |
| Просмотр истории своей заявки | Просмотр истории рассмотрения |

## Как проходит заявка

1. **Вход в кабинет.** Пользователь входит под заранее подготовленной учётной записью клиента или сотрудника. Самостоятельная регистрация в MVP не предусмотрена.
2. **Подача заявки.** Клиент выбирает сумму и срок кредитования, указывает сведения о бизнесе и отправляет заявку на рассмотрение.
3. **Проверка и расчёт.** Система использует финансовые данные и смоделированные ответы ФНС и БКИ для оценки заявки, расчёта ставки и доступной суммы.
4. **Решение.** По результатам оценки заявка получает решение, запрос уточнений или передаётся сотруднику для ручного рассмотрения.
5. **Предложение условий.** Клиент видит одобренные условия. Если исходный запрос нельзя удовлетворить полностью, сценарий предусматривает встречное предложение с изменёнными условиями.
6. **Согласие и выдача.** Клиент принимает предложение; подписание и выдача воспроизводятся внутри прототипа.

Изменения статуса и действия участников сохраняются в истории заявки, чтобы можно было проследить, как сформировалось итоговое решение.

## Как формируются условия

Механизм оценки сопоставляет запрошенные условия с данными о бизнесе и результатами проверок. На этой основе формируется рекомендация: одобрить заявку, предложить другие условия, запросить сведения, направить на ручное рассмотрение или отказать.

**Оценка заявки и окончательное решение — отдельные этапы.** Расчёт помогает определить условия и основания рекомендации, а кабинет сотрудника позволяет обработать случаи, требующие участия человека.

Для MVP используется упрощённая демонстрационная модель. Её задача — сделать логику кредитного процесса понятной и проверяемой.

## Что смоделировано

- **ФНС и БКИ:** ответы локальных имитаций внешних сервисов, без подключения к государственным и банковским системам.
- **Подписание:** подтверждение условий внутри интерфейса.
- **Выдача:** изменение состояния заявки без реального перевода денежных средств.
- **Клиенты, компании и финансовые показатели:** синтетические демонстрационные данные.

## Запуск

Нужны Docker Engine и Docker Compose v2 с поддержкой `up --wait`.

1. Выполните `make init`: создаст `.env` без перезаписи существующего.
2. Задайте `POSTGRES_PASSWORD`, `JWT_SECRET` и `TEST_USERS_PASSWORD`.
3. Запустите систему:

   ```bash
   make up
   ```

Для команд Makefile нужен Make. Без него запуск: `docker compose up --build -d --wait`.

| Адрес | Назначение |
|---|---|
| http://localhost:8080 | Кабинеты клиента и сотрудника |
| http://localhost:8000/docs | Swagger |
| http://localhost:8000/openapi.json | Точная схема API |

Compose запускает PostgreSQL 16, API и Nginx с фронтендом. Перед стартом API
применяются миграции и создаются тестовые аккаунты. Образы закреплены по digest,
библиотеки Python — точными версиями, зависимости фронтенда — package-lock.json.

| Переменная `.env` | Назначение |
|---|---|
| POSTGRES_PASSWORD | Пароль БД, обязательно |
| JWT_SECRET | Секрет подписи токенов, обязательно |
| TEST_USERS_PASSWORD | Начальный пароль тестовых аккаунтов, обязательно |
| WEB_PORT / API_PORT / DB_PORT | Порты, по умолчанию 8080 / 8000 / 5432 |

Порты доступны только на локальной машине. БД и документы хранятся в отдельных
именованных томах. Скачивание документов требует токен владельца или сотрудника.

```bash
docker compose restart
docker compose down
# Повторный запуск с теми же настройками и томами:
docker compose up -d --wait
```

`docker compose down -v` удаляет БД и документы.

## Тестовые аккаунты

Пароль — `TEST_USERS_PASSWORD`. Повторное создание аккаунтов сохраняет
существующие пароли. Публичной регистрации нет.

| Аккаунт | Сценарий |
|---|---|
| demo.ip@example.com | Встречное предложение |
| demo.review@example.com | Клиент: его заявка требует решения сотрудника |
| test.client1@example.com | Запрос выручки и полное одобрение при достаточном потоке |
| test.client2@example.com | Отказ по стоп-фактору |
| test.client3@example.com | Таймаут ФНС, повтор проверки и дозаполнение |
| test.employee1@example.com, test.employee2@example.com | Кабинет сотрудника |

## Основной сценарий

1. Войдите как `demo.ip@example.com`.
2. Выберите оборотный кредит: 1 000 000 ₽ на 24 месяца. ИНН берётся из профиля.
3. Сохраните черновик и отправьте заявку.
4. Проверьте встречное предложение около 609 641 ₽, ставку, платёж и объяснение DSCR.
5. Нажмите «Согласен с предложением» и подтвердите условия.
6. Перезагрузите страницу: согласованные условия и результат сохраняются.

Для ручного решения отправьте такой же запрос от `demo.review@example.com`.
Сотрудник видит факторы, выручку, расходы, денежный поток и обязательства;
может одобрить, отказать или запросить сведения с комментарием.

## Персонализированные новости

В кабинете клиента раскройте материалы блока «Новости для бизнеса».
Лента учитывает тип бизнеса и последнюю заявку. Для ИП и организации
показываются разные материалы; после решения появляется объяснение
встречного предложения, запроса сведений или другого результата.
Подбор использует только данные текущего клиента. Тексты синтетические.
[Сценарий показа двух клиентов](docs/TEST_SCENARIOS.md#персонализированная-лента).

## Устройство

React/Vite → Nginx → FastAPI → PostgreSQL. Маршруты проверяют права,
сервисы выполняют кредитный процесс, SQLAlchemy сохраняет данные.
Расчёт ставки и доступной суммы находится в `app/services/credit_math.py`.

Проверки выполняются синхронно. Их результаты, решение и история сохраняются
одной транзакцией. Версия заявки защищает от конкурирующих изменений;
устаревшее действие возвращает 409. CHECKING виден в истории, ответ содержит
итоговый статус. Клиент принимает сохранённое предложение.

## Разработка без Docker

Нужны Python 3.12.15 и PostgreSQL 16. Подготовьте `.env` по примеру и добавьте
`DATABASE_URL`, например `postgresql+psycopg2://user:password@localhost:5432/credit`.
`JWT_SECRET` и `TEST_USERS_PASSWORD` также должны быть заданы.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
alembic upgrade head
python -m app.seed_test_users
uvicorn app.main:app --reload
```

В PowerShell активируйте среду командой `.\.venv\Scripts\Activate.ps1`.
Для создания тестовых аккаунтов нужен `SEED_TEST_USERS=true`.
Файлы сохраняются в `storage/uploads`; другой каталог задаёт `UPLOAD_DIR`.
[Запуск фронтенда](frontend/README.md).

## Проверки

В активированной среде Python:

```bash
python -m pip install -r requirements-dev.txt
python -m pip check
python -m pytest
```

Основные API-тесты используют изолированную SQLite. Для проверки миграций
и конкурирующих действий задайте `CREDIT_TEST_POSTGRES_URL` на отдельную БД
PostgreSQL с правом создания схем, затем выполните `python -m pytest -m postgres`.
Тесты создают временные схемы и удаляют их после проверки. Без переменной
два PostgreSQL-теста пропускаются.

```bash
npm ci --prefix frontend
npm run lint --prefix frontend
npm test --prefix frontend
npm run build --prefix frontend
```

Проверено: 122 API-теста с PostgreSQL, 22 модульных теста фронтенда,
20 браузерных сценариев; коллекция — 31 запрос и 65 утверждений.
Отдельно проверено сохранение заявок, условий, истории и байтов документа
после остановки и запуска с сохранением томов.
